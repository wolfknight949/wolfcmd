# @wolfcmd/app

**Purpose:** the React 19 UI: title bar (workspace switcher with git worktrees, tab pills), tiled panels with terminals, the right bar (Agents; N-07 Settings at its foot). It owns the live workspace document and edits it; the core saves it.

## Layers (a layer imports only the ones before it)
1. `model/`: pure functions over the document (workspaces → tabs → tiled panels): N-03 panel contents (`panels.ts`: `terminalOf`, `agentOf`, `panelFolder`, `terminalPanel`, `changeTerminal`, `withCwd`, `missingType`), layout (split, close, N-03 move and swap, ratios, geometry, neighbors), N-03 maximize and the tab menu's actions (`document.ts`: `toggleMaximize`, `maximizedPanel`, `duplicateTab`, `closeOtherTabs`, `closeTabsToRight`, `renamePanel`), N-03 `drop.ts` (drop zones, the drag threshold, where a pill lands), `panel-title.ts` (a header's title: the user's, a program's own, the agent, the shell profile's name), N-01 `workspaceColor`, workspaces and tabs, agent panels across restarts (`agents.ts`: start folder, `running`, resume / pick), Remote Control rules, N-10 git worktrees (`document.ts`: `mainOf`, `worktreesOf`, `copyTabsInto`, `createWorktreeWorkspace`, `workspacePanels`; `worktrees.ts`: the menu rows, the default location, what a branch name means, "repo › branch"), N-11 the undo history (`history.ts`: `record` (grouping, `HISTORY_DEPTH`), `undo` / `redo` (contents kept from the present, where the user is kept unless they stayed where the step was made, `offscreen`), `undoablePanels`) and which closes ask (`close-rules.ts`: `runningIn`, `closeQuestion`). No React, no IPC.
2. `store/`: Zustand stores (workspaces (N-11: `apply(change, step?)` records a named step; `undo`, `redo`, `undoable`, `forget`; the state's `undo` / `redo` labels; every save carries the undoable panels), N-11 `commands.ts` (the shells running a command, from OSC 133, memory only), settings (N-07: `changed` merges one part, saves run one at a time and then only the newest, `saved()` waits for them), live titles (`titles.ts`; dropped once their panel leaves the document, `forgetTitles` from `main.tsx`), N-06 `agent-starts.ts` (`freshAgents`, `continuing`: how this run's agent panels start; set by `actions.ts`, read by `TerminalPanel`), N-02 panel attention and OSC 9;4 progress in `attention.ts`, memory only; N-06 agent activity in `activity.ts` (working, finished and whether its tab was seen since, the finished agent's color and the finish order, so a tab pill takes the latest finisher's color; memory only); `catalog`: the shell profiles, the agents and N-09 the plugin problems, read at start, the agents again when the Agents menu opens). A change is a `model/` function plus a save through `core/`.
3. `core/`: the only importer of `@wolfcmd/bindings` values and `@tauri-apps/api` (enforced by `@typescript-eslint/no-restricted-imports` in `eslint.config.js`; other layers may import the bindings' types): IPC wrappers: N-01 the native window (`window.ts`: its buttons and state, theme, drag, system menu, the maximize button's place and the caption overlay's hover; `quitApp`, the real quit, and `onWindowHidden`, the `window-hidden` event when closing hid the window to the tray), `app.ts` ( `openLink`: target, line, column, folder; the core decides what opens), native file drops (`drops.ts`), the terminal session client (`openTerminal`: attach or start, numbered writes, detach; opens of one panel run in order) and the saving health (`stateHealth` / `onStateHealth`, from `state_load` and the `state-health` event); N-10 `git.ts`: the worktree calls and the last listing of each folder (`knownRepositories`, read again each time the workspace menu opens, never polled). N-09 `agents.ts`: the agent list (`agentList`, `reloadAgents`) and `pluginProblemsLine`. N-06 `activity.ts`: the `agent-activity` and `show-panel` events (each listener returns its stop), `agentDone`. N-07 `about.ts`: `aboutApp` (version, commit, data folder) and `openDataFolder`. N-11 `window.ts` `onQuitRequested` (the tray's Quit while an agent runs) and `state.ts` `saveState(document, undoable)`. Other code never calls `invoke`, Tauri or the bindings' values.
4. `terminal/`: the xterm.js view (plain TS outside React, `terminal-view.ts`) and its pure, tested parts: OSC 133/52/9/777 (`osc.ts`), command marks (`marks.ts`), file links (`links.ts`), find in one output (`scoped-find.ts`), the Kitty keyboard protocol (`kitty.ts`, only with `terminal.kitty_keyboard`), image paste into agents (`image-paste.ts`), dropped paths quoted per shell (`drop.ts`), theme, the Dark Modern and Light schemes and the agent tint (`theme.ts`), title cleanup, agent drag-select, readiness.
5. `panels/`, `chrome/`: React components (N-03 `panels/types.ts`: the panel-type registry (`PanelType`: kind, `View`, `Header`, `add`), `builtin-types.ts` (`panelTypes`: the terminal, `TerminalType.tsx`), `UnknownPanel.tsx` (the placeholder for a kind nobody registered); N-06 `chrome/registry.ts`: a small ordered registry; `bar.ts` + `RightBar`: the right bar's items (`AddMenu`: + on top, then `AgentsMenu`: Agents; N-07 `placement: "bottom"` items at its foot: `SettingsButton`); `add-entries.ts`: what + offers; N-01 `chrome/density.ts` (the compact density below 1280 px), `chrome/theme.ts` (`data-theme` from the setting, Auto following the system) and `chrome/title-bar.ts` (the title bar per OS: caption buttons on Windows and Linux, room for the native traffic lights on macOS); `chrome/StateNotice`: the calm notices under the title bar when the workspaces aren't being saved, and N-01 the one hint about the tray (`chrome/tray-hint.ts`: the first `window-hidden` shows it for the window's return and sets `window.tray_hint_shown`, so it never shows again); `chrome/WorktreeDialog`: New worktree and Remove worktree on ui-kit `Dialog`; N-07 `chrome/SettingsDialog`: Settings, opened through `chrome/settings-open.ts` by the bar button, Ctrl+, and the workspace menu, with `chrome/fonts.ts`: installed monospace families found by canvas measurements). `TerminalPanel` owns the terminal's chrome: `FindBar`, `PasteConfirm`, `StickyHeader` (painted through a ref), `MarkMenu`, the agent's tint and top edge, and its drop handler (`panels/file-drops.ts`: one window listener, the panel under the pointer). `PanelHeader` shows attention (a bell) and progress, and N-06 `AgentIcon` / `AgentStatus` (the icon slot turns into a spinner in the agent's color while it works, then a check once it finished unseen; "Working…" or "Done" after the title); `chrome/TabPills` a dot on a tab that wants the user and N-06 `PillActivity` (one mark at a time in the pill's leading padding, so the name keeps its room: a small spinner while working beats the check of an unseen finish; one glow per unseen finish, in the finished agent's color (`data-agent`, `--wc-glow-agent` on the glow element; the latest finisher's when several did, the accent for an agent the catalog doesn't know), and the check in that color). N-06 `panels/PanelGlow` (the finish reward's overlay inside each block card, along its rounded edge in the agent's color; it listens to its own panel's entry outside React and plays through a ref) and `chrome/finish-glow.ts` (its rules: `createFinishGlow`, built in `main.tsx` with `appearance.finish_glow` and reduced motion; `pendingGlows`, a pending glow per panel in memory; `glowPlayed`). N-06 `chrome/WorkspaceActivity` (hidden workspaces' marks: the switcher's row hint and dot) and `chrome/agent-activity.ts` (installed by `main.tsx`, once: installing again replaces it; the core's events into the store with where the user looks (N-03: panels parked behind a maximized one are away), `agentDone` when the window is behind, clearing what the user now sees, the notification's click, and N-06 the finish glow: `finished` on every finish with where the user looks, `look` on document changes, focus and visibility, `forget` for panels that left). N-11 `chrome/CloseDialog` + `close-question.ts` (the one close question: `askToClose`, Cancel focused, "Don't ask again"), `chrome/UndoButtons` (Undo and Redo after the workspace switcher; tooltips name the step) and `chrome/UndoNotice` + `undo-notice.ts` (the moment's notice after an off-screen undo or redo). `actions.ts` (every user action in one place; N-01 `quit`: the settings saved, then the core quits; N-11 the undoable steps' labels, `undo` / `redo`, and `guarded`: every close asks first while something runs) and `keys.ts` (shortcuts; N-01 Ctrl+Q / Cmd+Q quits; N-11 Ctrl+Shift+Z undo, Ctrl+Shift+Y redo, never Ctrl+Z / Ctrl+Y) sit above them; `main.tsx` starts everything.

## Invariants
- **Terminals never go through React state.** Output goes from the IPC channel to `term.write`; React only mounts and unmounts the view.
- **Unmounting a terminal never ends its shell**: `dispose()` detaches, the next mount attaches (replay). Only a shell this view started fires `onReady` (agent start line, `terminal/readiness.ts`: an integrated shell waits for its prompt, others 5 s). Hidden terminals drop their WebGL context (`terminal/gpu.ts`) and get a new one, painted before the frame shows, when they come back; a context lost while shown is asked for again on the next frame (3 tries); disposing gives it back without building a DOM renderer. A view disposed before its open ran (StrictMode) never sends `pty_open` (`OpenOptions.cancelled`), so the next mount starts the shell and gets `onReady`.
- **N-06 agent activity:** working and idle come only from the core (events); "finished" is the UI's (a finish the user didn't look at). Marks re-render only on state changes (string selectors); nothing in React runs per output chunk. A finish never fires for the panel the user looks at; the pill's glow (once per unseen finish, in the agent's color) and the panel's finish glow play once and never under reduced motion.
- **N-06 the finish glow:** a finish in a panel the user isn't looking at makes that panel's own block glow once in the agent's color: at once when it is on screen (its tab shown, not parked behind a maximized panel, the window in front) and not focused, else when it comes on screen (its tab or workspace shown, the maximize ended, the window back: focus or visibility). Never for the panel the user looks at; a finish never glows twice; each panel glows on its own; nothing with `appearance.finish_glow` off or under reduced motion. The card never re-renders for it (`PanelGlow` subscribes outside React; `panels/TabView.test.tsx` checks). No timers: events only.
- **N-01 motion:** only `transform` and `opacity` animate, through CSS classes or Web Animations on refs (never per-frame React state), with durations and easings from tokens (`durationToken`, 0 under reduced motion). `TabView`: a new panel settles in (`data-settled` on the area: not the panels there at the start), maximize grows the card from its tile and restore shrinks it back (the card already at its new size: the terminal fits once and never blinks), the tiles that come back fade in, the focus border fades. `TabPills`: a new pill settles in, a closed one fades out where it was (ui-kit `leaveGhost`, no roles or hooks) while the others glide. The find bar, the paste question and dialogs leave through `useExitMotion`; notices slide in. Never terminal content, never a delay on input, never a timer while idle.
- **N-06 agent panels:** the agent line goes through `startAgent` (with the agent's id) (the core then reports `agentExited` → `running: false`); a restored panel starts in `AgentRef.cwd` and types only while `running`; the line is quoted for `pty_open`'s `profileId`.
- **N-06 the Add flyout (+) and its seam:** + lists the entries registered in `add-entries.ts` (`AddEntry`: id, label, icon, order, optional `note` and `choices` from the catalog, `open(actions)`); the bar knows none by name. Today the only entry is Terminal (no agent: the default shell, or one of the installed shells as its choices), opened next to the focused panel or as an empty tab's first panel. N-03: each panel type (`panels/types.ts`) offers its entry (`PanelType.add`) here (`main.tsx`: `offerAddEntries(panelTypes, addEntries)`, types registered later too); nothing else in the bar changes ([guide](../../docs/guides/panel-types.md)). A menu that opened a panel hands the keyboard to its terminal when it closes (`chrome/focus.ts`). N-02: a press on the chrome (a tab pill, its close and New tab buttons, the bar's and the caption's buttons) never takes the keyboard from the terminal (`keepKeyboard` in `chrome/focus.ts`); Settings gives it back to what had it.
- **N-03 panel types:** `TabView` draws a card's header and body through the type registered for `content.kind` (`typeFor`), never a switch on the kind; a kind nobody registered gets `UNKNOWN_TYPE` ("needs a newer WolfCmd" / "the plugin X", Close). Model code never rebuilds a content it doesn't know (the same object after split, move, swap, maximize, rename, close others, duplicate, copy into a worktree), so it is saved back untouched. Views share callbacks keyed by panel ID (`onChange`, `onFocus`, `onLayout`). [Design](../../docs/design/N-03-panel-types.md).
- **N-03 drags:** panel and pill drags use pointer events (the pointer captured at the press, a threshold, Esc or a lost capture cancels, no HTML5 drag and drop: native file drops are the terminal's) and paint through refs once a frame; the drop is one model change. A moved panel keeps its ID, so its card (keyed by panel ID) and terminal stay mounted. Headers carry `data-panel-header`, the preview `data-drop-zone` (with `data-shown` / `data-zone`).
- **N-03 context menus** (`chrome/context-menus.ts`: the items per object, pure and tested; ui-kit `ContextMenu`): tab pills, panel headers (`PanelHeader`), terminals (`panels/TerminalMenu`, opened by the view's `onContextMenu`) and workspace rows (`MenuItem.contextMenu`, Rename… in `chrome/RenameDialog`). Only the expected items, each with its key; nothing on empty chrome. `keys.ts` turns Shift+F10 / the Menu key into a keyboard-marked `contextmenu` on the focused element. A terminal's right-click: `terminal/context-menu.ts` (quick copy/paste on Windows, the menu with Shift, from the keys or elsewhere; the program's while it tracks the mouse). [Design](../../docs/design/N-03-context-menus-and-maximize.md).
- **N-03 maximize:** `Tab.maximized` (`maximizedPanel`, `toggleMaximize`); `TabView` gives that card the area and parks the tab's others like a hidden tab's (`visible: false`, never unmounted). A split, a drop, the start of a header drag, closing it or focusing a hidden panel end it.
- **N-03 no render storms:** a model change that changes nothing returns the same document; `TabView` cards are memoized, take shared callbacks keyed by panel ID (never a closure per panel per render) and cached per-tab geometry; divider drags stay local until pointerup (and end unsaved when their divider goes away: another tab shown, a maximize, a close). `panels/TabView.test.tsx` counts TerminalPanel renders: keep it passing.
- **N-02 the terminal's chrome** (find bar, paste question, command menu, attention) is React state that changes only on user actions and at OSC marks, never per output chunk; the sticky header follows scrolling through a ref. Shortcuts use `primaryModifier` (Cmd on macOS, Ctrl elsewhere); nothing in the UI assumes Windows (dropped paths are quoted by the profile that runs).
- **N-07 settings** apply at once (no OK/Cancel, only Close) through `SettingsStore.apply`; a text field (the font) applies on Enter, when it loses the focus or when it names an installed family, never per keystroke. The default shell is the core's to resolve (`WOLFCMD_DEFAULT_PROFILE` first); after changing it the profiles are read again once saved. [Design](../../docs/design/N-07-settings.md).
- No web-isms: no text selection on chrome, no browser context menu, no layout shifts on load.
- **N-10 worktrees:** a worktree workspace is a workspace with `main` (its folder is the worktree). Copied tabs get fresh tab, split and panel IDs, folders moved into the worktree and fresh agents (new session IDs, `running`, added to `freshAgents`). Removing goes through the core, which ends the workspace's terminals first; the workspace closes only after git succeeded. While a dialog is open (`modalOpen()`), shortcuts and the empty tab's Enter leave the keys to it.
- **N-11 undo:** only actions name steps (`store.apply(change, { label, group? })`); where the user looks (showing a tab or workspace, the focus) and what terminals report (`onChange`: a folder, an agent's end) are never steps, and undo keeps the present panel contents. A divider drag is one step (`resize:<split>`), renames group by ID. Every save sends `undoable` so the core keeps those closed panels' sessions for the grace: never drop it. Removing a worktree calls `forget` (and passes the undoable panels to the core, which ends them with the worktree's own).
- **N-11 closes:** every close goes through an action and `guarded` (the ✕ buttons, middle-click, Ctrl+Shift+W, the context menus, the workspace menu, the unknown-kind card); never `store.apply(closePanel…)` from a component. Idle panels never ask; the quit asks only for agents; closing the window to the tray never asks. [Design](../../docs/design/N-11-undo-and-close-confirmation.md).
- Colors, sizes and primitives come from `@wolfcmd/ui-kit` (`--wc-*` tokens; its CLAUDE.md lists the scales); no hard-coded colors or bracketed values (the `wolfcmd/design-tokens` ESLint rule).
- Model functions return a new document and never mutate; tests cover every operation.
- **N-03 resizing never blinks:** after anything that resizes or replaces a shown terminal's canvas (fit, xterm's device-pixel resize, a WebGL context coming back, the terminal coming back on screen) the view paints at once (`terminal/paint.ts`, xterm's render service; `refresh` if its internals change). Fit runs inside the `ResizeObserver` callback; hidden and 0×0 terminals keep their size; `setVisible` runs in a layout effect; the PTY resize waits for the size to settle (100 ms, flushed two frames after a pointerup) and is skipped when the shell already has that size. `tests/e2e/src/resize.e2e.ts` (WebGL on) fails on a single blank frame.
- Panels mount only once the panel area has its size (`TabView`): a terminal opened in a 0×0 box asks for a 2×1 shell, and attaching at that size reflows a running one. Panel cards carry `data-panel` / `data-focused`; the end-to-end tests (`tests/e2e`) find panels by them.

# @wolfcmd/e2e

**Purpose:** end-to-end tests that drive the real `WolfCmd.exe` like a user: keys and clicks in its WebView2 page, the terminal's text, the saved files, kills and restarts. Windows only.

## Run
- `pnpm e2e` (root): builds the debug app with the UI embedded (`pnpm e2e:build`, `tauri build --debug --no-bundle`), then runs every scenario. `pnpm --filter @wolfcmd/e2e e2e` runs them against the build that is there (`-t "N-05"` picks scenarios by name).
- **Not part of `pnpm check`:** it needs a desktop session, opens real windows (each takes the foreground when it opens; N-02: the harness hands it straight back to the window that had it, since keys typed there would land in the scenario's terminal; focus is emulated over DevTools), starts real shells and takes about two minutes. Run it before a release and after changes to terminals, the layout, workspaces or saving.
- A screenshot per scenario lands in `tests/e2e/screenshots/` (git-ignored); a failed scenario leaves `FAILED-<name>.png` and `FAILED-<name>.log` (`Sandbox.finish` in `afterEach`: the process's exit, DevTools disconnects, page crashes, closes, reloads and script errors, timed from the launch, then the app's own log, its stderr).

## How it works (`src/harness.ts`, `src/ui.ts`)
- Each scenario gets a `Sandbox`: a fresh temp folder with the data folder (`WOLFCMD_DATA_DIR`), its own WebView2 profile (`WEBVIEW2_USER_DATA_FOLDER`) and a `bin` folder first on WolfCmd's PATH. `dispose` (in `afterEach`) kills the app's process tree and removes the folder; an exit hook kills anything left.
- `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` opens a DevTools port; `playwright-core` connects with `connectOverCDP` (no browser download). WebGL is turned off there unless a scenario asks for it, so xterm uses its DOM renderer and `screen()` reads the rows (text only; a wrapped row reads as two, `joined` runs them together).
- N-03 blink scenarios (`src/resize.e2e.ts`, helpers in `src/frames.ts`) launch with `launch({ webgl: true })`, what users run. A probe in the page checks every painted frame (a WebGL canvas resized or created and not drawn before the paint, a terminal without text or gone) and counts `pty_resize` / `pty_open` (fetches of `ipc.localhost`; Tauri's `invoke` can't be wrapped). `nativeFrames` drives the window through Win32 from one PowerShell (moves, sizes, maximize, minimize, restore; on top while watched) and compares screen captures with the first one (text gone, colors the window never has). Captures, a contact sheet and `report.json` land in `screenshots/frames-<name>/` (`WOLFCMD_E2E_FRAMES` moves them). With WebGL `screen()` can't read the rows: wait with `waitForQuiet` (no draw for 300 ms, under the cursor's 600 ms blink).
- `WOLFCMD_DEFAULT_PROFILE=cmd`: every terminal is Command Prompt, without the user's PowerShell profile.
- N-02 `src/typing.e2e.ts`: long lines typed with no wait right after what moves the keyboard or animates near it (a new panel, clicks on panels and tab pills, Ctrl+Tab, menus and the + flyout closing by Esc, an item or a click on a terminal, Settings closing, an agent's spinner, a finish glow), a few rounds; `keys-probe.ts` checks that every key reached the terminal meant and its shell echoed the line exactly, and shows the keys and focus changes when not. The stand-in agent lives in `stub-agent.ts`.
- Scenarios: `app.e2e.ts` (terminals, layout, workspaces, saving, agents, N-03 a format 1 `workspaces.json` migrated: its panels and shells, the `workspaces.v1-*.json` copy, format 2 on disk), `menus.e2e.ts` (N-03 context menus and maximize; N-02 the command marks as slim lines on the scrollbar track at a maximized panel's edge, read from the ruler's pixels), N-01 `tray.e2e.ts` (the window's Close hides WolfCmd: the process and its terminal keep running, the app's own window is hidden (`windowShown`; `APP_WINDOW` finds the titled window, never the event loop's sizeless helper window, which Windows may name as the main window), the tray hint is remembered in `settings.toml` and waits under the title bar, Ctrl+Q quits and saves), N-07 `settings.e2e.ts` (Ctrl+, Light restyles the window and the terminal, a bigger font reflows the shell once (`pty_resize` counted), Esc gives the terminal the keyboard back, a restart keeps both; `WOLFCMD_E2E_SETTINGS_SHOTS` copies its dark and light screenshots of each section to a folder).
- N-06 `src/activity.e2e.ts`: a stand-in `claude.cmd` runs a PowerShell script that sets Claude Code's titles through the console (ConPTY sends OSC 0) and prints for 4 s per typed line; agent marks are found by `data-activity` (pills, headers, the switcher button), the pill's glow by `data-pill-glow[data-glowing]` and a panel's finish glow by `[data-panel] [data-panel-glow][data-glowing]` (when its tab or workspace comes back, at once for a finish in the shown tab with another panel focused, none for a finish in the focused panel). The opt-in showcase (`showcase.e2e.ts`, `WOLFCMD_SHOWCASE=<folder>`) freezes the glows (their animations paused and sought) for stills (two agents' panels glowing in their colors), dark and light, and a frame sequence (`glow-frames-*.png`). `WOLFCMD_E2E_ACTIVITY_SHOTS` copies its screenshots (dark and light) to a folder.
- N-02 `src/repaint.e2e.ts` (WebGL on): a stand-in full-screen agent (a node script: alternate screen, synchronized output, only changed rows rewritten, mouse motion; it redraws on its own, a `pause` file next to it holds it still) while the scenario shows another tab and back, splits, maximizes, opens Settings and the Agents menu and hovers. `src/painted.ts`: `findTerminals` keeps xterm's `Terminal` objects on the page (DevTools `Runtime.queryObjects`), `bufferRows` reads a panel's buffer, `stalePaint` returns the rows whose pixels change when the renderer draws everything afresh (stale paint), `holdRendering` proves the check sees a missed paint.
- N-11 `src/undo.e2e.ts`: the close question (`getByRole("dialog")`; a stand-in agent asks, Enter on the focused Cancel keeps it, Close closes) and undo / redo by Ctrl+Shift+Z / Ctrl+Shift+Y (the agent panel back with its text and still running, a closed tab back and gone again; the buttons found by their tooltip `Undo close panel…`), and an undo in another tab showing its notice (`getByRole("status")`). `quit()` answers Quit when WolfCmd asks (an agent running).
- N-01: panels and pills animate (a new panel settles in, maximize grows a card from its tile): `panelBox` waits for the panel's own animations to end before measuring it.
- Panels are found by `data-panel` and the focused one by `data-focused` (`packages/app/src/panels/TabView.tsx`), a panel's header by `data-panel-header` and the drop preview by `data-drop-zone[data-shown]`; keep those attributes. The Agents button is in the right bar (found by its name).
- N-01: closing the window hides WolfCmd to the tray by default, so scenarios end a run with `quit()` (Ctrl+Q, waits for the exit); `closeWindow()` (Close, waits for the exit) only with `window.close_to_tray = false` in the sandbox's `settings.toml` (the bounds scenario), `hide()` for the tray. A second launch showing a hidden window (single instance) isn't covered: debug and sandboxed builds leave the handoff out.
- The window's bounds go through Win32 (`powershell.exe` + `Add-Type`, per-monitor DPI aware: physical pixels like `window.json`).

## Invariants
- Never start a real agent: the agent scenario puts a stand-in `claude.cmd` in the panel's folder (Command Prompt looks there first; the harness drops `NoDefaultCurrentDirectoryInExePath`, which Claude Code sets) and checks that `claude --version` runs the stand-in before it opens the agent. A shell's PATH comes from the registry, not from WolfCmd's environment.
- Nothing outside the sandbox is written; the user's own WolfCmd data and windows are never touched.
- Wait for what a user would see (a prompt, a panel, a notice), never for fixed times, except to prove that something does *not* happen.

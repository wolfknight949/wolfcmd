# wcmd-app

**Purpose:** `WolfCmd.exe`: the Tauri 2 app. The window, terminal sessions, the saved workspace, settings and agent launch lines. The UI (`packages/app`) does everything else.

## Layout
- `src/lib.rs`: `run()` (start order: data folder, state, window, IPC); `src/main.rs` only calls it.
- `src/ipc/`: the 26 commands and the five events (`CaptionButtonChanged`, `StateHealth`, N-06 `AgentActivity`, `ShowPanel`, N-01 `WindowHidden`), registered in `specta_builder()`. A new command is also listed in `build.rs` and `capabilities/main.json` (a test checks all three). N-07: `app_about` (version, the build's commit, the data folder) and `app_open_data_folder` (the file manager there); `ipc/settings.rs` `SettingsService` reads `settings.toml` once at start and keeps it (its getters `theme`, `default_profile`, `agents`, N-01 `close_to_tray` never touch the disk; `settings_save` writes the file and updates the copy; in a read-only run, a file that couldn't be read or kept aside, the change applies but the file is never written and the save returns an `unavailable` error saying why). `SettingsService::default_profile` is the default shell setting, which `LocalSessionHost::with_default_profile` asks at each start without a profile (`default_profile()`: `WOLFCMD_DEFAULT_PROFILE`, then the setting when installed, then the first installed), as do `pty_list_profiles`' default mark and `agent_command` for a panel without a profile.
- `src/ipc/agents.rs`: N-06 agents: `agent_list` (installed first; N-09 each agent's `plugin`, and `problems`: what in `<data dir>/plugins` couldn't be used) and `agent_command` (the line, quoted for the panel's shell). Both ask the `wcmd_agents::AgentRegistry` in Tauri state, which reads the plugins folder again only when it changed. N-06 `agent_done` (an agent finished unseen, the window behind: `platform::flash_taskbar`, and with `agents.notify_when_done` `platform::notify`, names only; a click reveals the window and emits `ShowPanel`); the `AgentActivity` event (`{ panelId, working }`) is emitted from the session host's sink set in `lib.rs`.
- `src/session/`: `LocalSessionHost` runs each shell under ConPTY in-process and keeps its VT state (`wcmd-term`). `open` attaches a view to its panel's running session (replay, then the output after a stream offset) or starts one; one shell per panel, opens of one panel or request wait for each other (never a global lock while spawning). Output goes to the attached view with flow control (`flow.rs`: the view acknowledges, the reader pauses above the limit; never while detached, nor N-01 while the window is hidden to the tray (`set_background`): a hidden view then gets output until it is the limit behind, then nothing until the window shows and `catch_up` sends it a reset (RIS) and the screen replay, the stream going on from that offset), batched per frame (`batcher.rs`); input is written in sequence order once (`input_order.rs`). The `session-keeper` thread saves quiet sessions' scrollback and ends orphans; `snapshot_store.rs` keeps and restores scrollback. N-06: `pty_open` also returns the profile really run (`profile_id`), `integrated` (prompt marks expected; never for WSL) and `agent_exited`; a `pty_write` with `agent` is the agent's line, and the prompt mark after it (`Vt::agent`, `AgentWatch`) is reported once as `SessionEvent::AgentExited`. N-06 `activity.rs`: while the agent runs, `ActivityWatch` (in `Vt`, fed by the reader per chunk: the title via `Terminal::take_title`, then the output) says working or idle: the agent's `working_title` (looked up by the `pty_write`'s `agent` id through `with_title_patterns`) once it matched, else output activity after a submit (`InputMarks`: atomics written by `write` and `resize`); the keeper's tick (`tick_activity`) ends a quiet spell; changes go to `on_activity`'s sink, never per chunk otherwise; `pty_open` returns `agent_working`. N-03: a folder report goes to the view only when it changed (`Vt::reported_cwd`).
- `src/git.rs` (N-10): git worktrees: `worktrees(folder)` (the repository: the folder's worktree root, the main tree, `git worktree list --porcelain -z`, the local branches; `None` outside a repository or without git), `add` (validated: a full path, new or empty, not inside a linked worktree; a valid branch name), `check_removable` (never the main tree; refuses changes or a lock unless forced) and `remove` (run from the main tree; a deletion a closing process still blocks is retried). Git runs with `CREATE_NO_WINDOW`, `GIT_TERMINAL_PROMPT=0`, a timeout (then it and every process it started are ended: `platform::kill_tree`, `taskkill /T /F` on Windows) and git's own message as the error; its output is read for at most `PIPE_GRACE` (2 s) after it exits, so a process it left running (a hook's background job) never holds a call; no git at all is `RunError::Missing` (`worktrees` answers `None`); `ipc/git.rs` runs it on the blocking pool. Removing first ends the workspace's terminals (`LocalSessionHost::end_panels` waits until their pseudo consoles are closed), only after the checks passed.
- `src/tray.rs` (N-01): closing the window hides it to the tray instead of quitting. `install` (in `setup`) builds the tray icon (the app's icon, "WolfCmd"; left click: `show`; menu: Show WolfCmd, a separator, Quit WolfCmd) and handles `CloseRequested` with the pure `decide(request, close_to_tray, can_hide)`: only the window's own close (✕, Alt+F4, the taskbar) with the setting on and something to bring it back hides (`prevent_close`, `WindowHidden { tray }` to the page); a quit, the setting off or no tray (a Linux desktop without one) quits. `quit` (the tray's Quit, `ipc::app::app_quit` for Ctrl+Q) marks quitting and calls `AppHandle::exit`, so `RunEvent::Exit` does the usual flush; `ExitRequested` marks quitting too. `show` (unminimize, `ipc::app::reveal`) is what a second launch (single instance), the finish notification's click, the tray and macOS's Dock (`platform::is_reopen`) use. `hidden()` tells the watchdog. macOS: `platform::DOCK_SHOWS_HIDDEN_WINDOW` (the red button hides, the Dock brings it back, no tray icon).
- `src/watchdog.rs`: pings the page every 2 s while shown (N-01: never while hidden to the tray, `tray::hidden`); reloads it after 10 s of silence (pure `Watch` state machine, fake-clock tests).
- `src/state.rs`: `StateService`: the workspace document and window bounds; a writer thread saves the newest document at once and retries a failed save (200 ms doubling to 5 s) unless a newer one replaced it (numbered, so an older one never lands over a newer one); `StateHealth` (read-only reason, failing save, start note) goes to the UI with `state_load` and as the `state-health` event (`on_health`, connected by `state_load`); `flush()` waits for the writer at most 5 s, then writes on the calling thread (true only when nothing is queued or being written); N-05 `freeze()` (Windows ending the session, `WM_QUERYENDSESSION`, and quit) stops writing later documents, so an agent the shutdown ended is not saved as ended and is resumed at the next start; `thaw()` (the end was cancelled: `WM_ENDSESSION` with `wParam` 0) writes the newest one and resumes; `is_fallback()` is true when the document did not come from a good file (per-panel cleanup must skip). At start `retire_old_data` sets an earlier data folder of a different format (`state.db` without `workspaces.json`) aside as `<name>.old`; nothing is deleted.
- `src/window_bounds.rs`: pure placement of the window on a monitor (several monitors, scale changes, snapped, maximized).
- `src/open.rs`: N-02 what a Ctrl+clicked terminal link opens (pure `plan`, tested): web and mail links, files in VS Code at the line (else their default app), folders; executables and scripts are revealed, never run (by extension, read as Windows reads it: trailing dots and spaces dropped, alternate data streams refused; and on Windows any type `AssocIsDangerous` names; by the executable bit outside Windows); network shares and device paths are refused before the disk is touched. `ipc::app::app_open_link` carries it out; `platform::reveal_path` quotes the path in Explorer's `/select,"…"`.
- `src/platform/`: the OS boundary, one set of functions. Windows: `windows.rs` (WebView2 hardening, window rectangle, open and reveal, clipboard, background commands, N-10 `kill_tree`), `caption.rs` (Snap Layouts for the custom maximize button), `lifecycle.rs` (window shown, WebView2 `ProcessFailed` → reload, `WM_QUERYENDSESSION`/`WM_ENDSESSION` → freeze the state and save everything, also while hidden to the tray; a cancelled end → thaw; N-01 `DOCK_SHOWS_HIDDEN_WINDOW` false and `is_reopen` false: the tray brings the window back), `folder_dialog.rs`, `local_time.rs`, N-06 `notify.rs` (`flash_taskbar`: `FlashWindowEx` until the window is in front; `notify`: a WinRT toast, the app's identifier or PowerShell's for a build in `target`, its click handler kept with it). N-01: `tauri.macos.conf.json` gives macOS the native traffic lights over our title bar (`titleBarStyle: "Overlay"`, hidden title); Windows and Linux stay frameless with our caption buttons. macOS and Linux: `other.rs` (the same functions: the desktop opener `open` / `xdg-open`, no-op window chrome, no dialogs yet; N-06 the window's attention request instead of the flash, no notification yet; N-01 `DOCK_SHOWS_HIDDEN_WINDOW` and `is_reopen`: macOS hides to the Dock, Linux uses the tray), so the crate builds there.
- `examples/gen-bindings.rs`: writes `packages/bindings/src/index.ts` (`pnpm gen:bindings`; debug runs of the app also keep it current).

## Depends on / used by
- Depends on: every other `wcmd-*` crate, `tauri` (with single-instance; N-01 the `tray-icon` feature), `tauri-specta`. Used by: nothing (the top of the stack).

## Invariants
- The core never touches the DOM or React state; the UI never touches files. They meet at the IPC commands.
- `unsafe` lives only in `src/platform/`, each block with a `// SAFETY:` comment.
- Terminal output goes from the session straight to the UI channel as raw bytes.
- **A page never ends a terminal.** Page load detaches every view (`detach_all`); a session ends only by its terminal panel leaving the document (`ipc/state.rs` `state_save`; N-03 only terminal panels have sessions: `StateService::terminal_ids` / `has_terminal`), the orphan sweep, its shell exiting, the removal of its worktree (N-10 `git_worktree_remove`, after the user confirmed), or quit (`kill_all`; N-01 the tray's Quit or Ctrl+Q, never the window's close while it hides to the tray). A view attached to a running session gets its replay and every later byte exactly once, and the UI never types into it.
- Locks: a session's `vt` before its `view` and its input `order` (never `vt` under `order`); the `Reports` slot and the `SnapshotStore`'s `staged` map are innermost (N-05 a snapshot is staged under its session's `vt`, so stagers stage in the order they copied); nothing slow (spawn, folder check, closing a pseudo console) under the `sessions` or `opening` lock.
- Nothing is sent to the network or an agent without a user action.
- N-03: the window's and web view's background is `--wc-bg-subtle` for the theme setting (`startup::background_for`; Auto: the system's); the UI follows theme changes with `setBackgroundColor` (`core:window:allow-set-background-color`, `core:webview:allow-set-webview-background-color`).
- The window starts hidden and shows when the UI reports its first frame (`app_window_ready`), or after `SHOW_FALLBACK`.
- N-01: closing the window never ends anything while `window.close_to_tray` is on: it hides (`tray.rs`); only quit (`tray::quit`, then `RunEvent::Exit`) ends the sessions.
- Data folder: `WOLFCMD_DATA_DIR`, else `%APPDATA%\WolfCmd` (`WolfCmd-dev` in debug builds). N-09 plugins are read from its `plugins` folder (never written or created).

## How to test
- `cargo test -p wcmd-app`; `pnpm dev` for the running app. `session/local.rs` has real-ConPTY tests (cmd) for reattach, the StrictMode double open, an attach during a flood, a detached flood, closed/orphaned panels, an agent's exit (live and on reattach), N-06 an agent's working title reported working and idle (a nested cmd's `title`, detached and on reattach), the folder reported once and a gone profile (cmd with integration for the last ones), and ended panels releasing their folder (N-10). `git.rs` tests run real `git` in temp repositories with spaces in their paths (list, add new and existing branches, refusals, remove clean, dirty refused, forced; a process left holding git's output, a timeout ending the whole tree).

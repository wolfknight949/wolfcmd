# Roadmap

> Status: Current · What WolfCmd is building, by feature ([ADR-0001](adr/0001-founding-architecture.md)). A feature is added only when users ask for it.

**Guiding rules:** a clean architecture with no dead code (everything inside is used); hot reload in dev mode. Every change is judged by how working with one or two terminals feels: fast, calm, native. No extra panels, no suggestions, no process models.

Feature IDs are `N-xx`. Statuses: ⬜ to do · 🔨 in progress · ✔️ done.

## Version 0.5.0: terminal and workspaces

| ID | Feature | Status | Notes |
|---|---|---|---|
| N-01 | Window and design | 🔨 | Frameless window with our title bar (Snap Layouts on Windows, native traffic lights on macOS), a solid background, no web-isms; closing hides it to the tray (the setting `window.close_to_tray`, on by default: terminals and agents keep running; Quit in the tray's menu or Ctrl+Q; macOS: the Dock). One cross-platform look of our own (calm and warm; Lucide line icons, the system UI font, soft shapes, a warm neutral ramp, one light blue-violet accent, the focused block outlined in it), dark by default (Light and Auto as choices) with the Dark Modern and Light terminal schemes, every value from design tokens (an ESLint rule keeps class lists on the scales; a test checks text and icon contrast in both themes), opaque menus, workspace accent colors (the switcher dot, the focused panel's border), a compact density in small windows; calm motion (hover fills and gentle presses everywhere, things fade and settle in and out, maximize grows the block from its tile; transform and opacity only, token durations, none under reduced motion) |
| N-02 | Terminal | 🔨 | ConPTY (patched portable-pty), xterm.js with WebGL (DOM fallback), shell profiles (PowerShell, cmd, Git Bash, WSL), copy/paste (right-click too, multi-line paste guard), Ctrl+click links (URLs, OSC 8, `path:line:col` opened safely by the core), find (case, regex, count, one command's output), command marks from OSC 133 (gutter dots, Ctrl+Up/Down, sticky header, a command's menu), attention (OSC 9/777, bell) and OSC 9;4 progress on the panel and its tab, cwd from shell integration, Shift+Enter, IME, kitty keyboard (setting, off), image paste into agents, files dropped from Explorer as quoted paths, agent panels tinted with the agent's color, smooth scrolling, drag selection in agent TUIs, flow control. Cmd on macOS where Windows uses Ctrl |
| N-03 | Tabs and splits | 🔨 | The Wave model: a workspace's tabs as pills in the title bar, easy to switch (click, Ctrl+Tab, Ctrl+Alt+1…9, Ctrl+Shift+T new); a tab is tiled panels: split right/down, Alt+arrows, resize by dragging, close. Drag and drop: a panel's header onto a drop zone (a side splits there, the centre swaps; its shell keeps running), tab pills sideways to reorder; Esc cancels. Context menus on tab pills, panel headers, terminals and workspace rows (right-click, Shift+F10, the Menu key; only the expected actions, each with its key; a right-click in a terminal still copies or pastes on Windows, Shift+right-click opens its menu). Maximize a panel (button, double-click on the header, Ctrl+Shift+Enter): the others stay mounted and hidden, saved across restarts ([design](design/N-03-context-menus-and-maximize.md)). Resizing never blinks: a resized, re-shown or re-created WebGL canvas is painted in the same frame, the shell reflows once per settled size (100 ms, or a released divider), hidden terminals keep their size, and the window background is the theme's; `tests/e2e/src/resize.e2e.ts` checks every painted frame. Panel types ([design](design/N-03-panel-types.md), [guide](guides/panel-types.md)): a panel's content is tagged by its kind (document format 2, format 1 migrated with a copy kept), cards are drawn through a panel-type registry (Terminal registered), and a kind this WolfCmd lacks shows a calm card and is saved back untouched |
| N-04 | Workspaces | 🔨 | No sidebar: the workspace name at the top left opens the workspace switcher: every workspace, New workspace, Open folder… (a workspace with a folder), its Remote Control and Close |
| N-05 | Session restore | 🔨 | Robust save: every change saved crash-safe at once; workspaces, splits, folders, window bounds and scrollback come back after a restart |
| N-06 | Agents | 🔨 | The slim bar on the right edge (a registry of bar items, so plugins' buttons can join) holds + (the Add flyout: registered add entries; today Terminal with the installed shells as choices, the seam for more panel types) and Agents. The Agents button lists the installed agents (Claude Code, Codex, Gemini CLI, Copilot CLI, Aider, OpenCode, and agents plugins add); choosing one opens a terminal panel running it. No harness, no status hooks, no agent flows: a terminal and workspaces, as in Wave Terminal. After a restart an agent panel resumes its own session in the folder it started in (Claude Code: WolfCmd picks the `--session-id`, and a session Claude Code never saved starts anew with that ID; others: their latest session in the folder, a second panel of the agent there opens its picker); an agent that ended (the shell back at its prompt) is not started again. Remote Control per workspace folder. Agent activity ([design](design/N-06-agent-activity.md)): working and finished on the panel header, the tab pill (one mark in its leading padding; one glow in the finished agent's color when it finished unseen, the latest finisher's when several did, then a check in that color until the tab is shown), the finished agent's panel glowing once in its color (when the user can see it, never for the focused panel; `appearance.finish_glow`) and the workspace switcher, from the agent's own title or output activity (no hooks); with the window behind, the taskbar button flashes and an optional notification (`agents.notify_when_done`) names the agent and tab |
| N-10 | Git worktrees | ✔️ | Separate tasks in one repository: a workspace's worktrees in the workspace menu, New worktree (empty or copying the main tree's tabs), switch, remove ([design](design/N-10-worktrees.md)) |
| N-09 | Plugins | ✔️ | A small, clean plugin system: a plugin is a folder `<data dir>/plugins/<id>/` with a `plugin.toml` that declares data (WolfCmd never runs plugin code); first contribution point: agents, shaped like the built-in ones, never replacing one; problems show as one calm line in the Agents menu; read again when the menu opens, never polled. More points only when users ask ([design](design/N-09-plugins.md), [guide](guides/plugins.md)) |
| N-07 | Settings | ✔️ | One small dialog (the gear at the right bar's foot, Ctrl+, or the workspace menu): theme (Dark Modern, Light, Auto), font with installed monospace suggestions, size, cursor, smooth scrolling; default shell, Kitty keyboard; Remote Control by default, notify when an agent finishes; N-01 keep running in the tray when closed; About (version, data folder). Every change applies and saves at once ([design](design/N-07-settings.md)) |
| N-08 | Distribution | ⬜ | winget, installers published as this repository's releases, no in-app updater ([ADR-0004](adr/0004-open-source-and-releases.md)); an earlier data folder of a different format in `%APPDATA%\WolfCmd` is set aside as `WolfCmd.old`, never deleted |

## Later

## Performance budgets
- Window shown with a live prompt in under 500 ms on a warm start.
- A key reaches the screen in under 10 ms; drags and resizes at 60 fps; terminals never go through React state.
- Nothing polls while the window is idle.

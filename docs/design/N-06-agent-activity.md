# N-06: Agent activity (working, finished)

> Status: Implemented · [Roadmap](../ROADMAP.md) N-06: indicators that an agent is working on its tab and panel, and a calm, rewarding sign when it finishes: the finished agent's panel and tab glow once in the agent's color

## Goal
See at a glance which agent is working, and notice calmly when one is done, without looking at its panel. No hooks and no harness: WolfCmd reads only what the terminal already sees, and never writes into a project or an agent's settings.

## States (per agent panel, only while `AgentRef.running`)
| State | Meaning | Where it lives |
|---|---|---|
| idle | the agent waits for the user | the core (`working: false`) |
| working | the agent is busy | the core (`working: true`) |
| finished | it went from working to idle and the user hasn't looked at the panel yet | the UI (`store/activity.ts`) |

The core knows only working and idle; "finished" depends on what the user looks at, so the UI keeps it. A panel finishing while the user looks at it (focused, its tab shown, the window in front) goes straight to idle: nothing fires. A plain shell's long command keeps raising N-02 attention (the bell and the pill's dot); it is not an agent state.

## Signals (in the core's session reader, `session/activity.rs`)
1. **The agent's own title** (where the agent has one). An agent TOML may declare `working_title`, a regex matched against the terminal title (OSC 0/2). Once it has matched, the title alone decides: matching is working, anything else idle. Verified against each CLI (the TOMLs quote the evidence):
   - Claude Code 2.1.292 (its bundled source): `◐`/`◑` alternating every 960 ms before the title while busy (frozen, not removed, while its terminal is unfocused), `✳` when idle; static `✳` under tmux/screen/zellij; no title with `CLAUDE_CODE_DISABLE_TERMINAL_TITLE`. Pattern `^[◐◑] `.
   - Codex (openai/codex `tui/src/chatwidget/status_surfaces.rs`): a Braille spinner frame (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`, 100 ms) as the title's "activity" item while a task runs (first by default, movable), nothing when idle. Pattern: one frame as its own word.
   - Gemini CLI (`packages/cli/src/utils/windowTitle.ts`): `✦` while responding, `⏲` while working silently, `◇ Ready` idle, `✋ Action Required` waiting for a confirmation (idle: it wants the user). Pattern `^[✦⏲]`.
   - Copilot CLI, Aider, OpenCode: no title behaviour verified; activity only.
2. **Output activity** (every agent until its title matched once). Output that comes more than 300 ms after the last input (keystrokes, pastes, terminal replies, a resize: their echo and redraws don't count) and lasts at least 1 s (gaps under 1 s) is working; no such output for 2 s is idle. Activity starts counting only after the user submitted something (Enter) since the agent started, so an agent drawing its screen at start or a restored session replaying its history never "works".
3. **OSC 9 / 777 and the bell** keep meaning "wants the user" (N-02 attention), unchanged.

Cost: the reader already locks the VT state per chunk; the watch adds a few comparisons and, only when the title changed, one regex match. Input time is an atomic. Idle needs a clock: the session keeper's existing 1 s tick checks working sessions (none while every agent is idle), so detection takes 2–3 s and no new timer exists. Works with no view attached.

Reported only on change, as the `agent-activity` event (`{ panelId, working }`); `pty_open` returns `agentWorking` so a reloaded page starts right. The agent's exit (N-06 `agentExited`) ends the watch (idle).

## UI
- **Panel header** (`panels/AgentActivity.tsx`: `AgentIcon` in the icon slot, `AgentStatus` after the title): working turns the panel's icon into a small spinner (ui-kit `Spinner`) in the agent's color with a quiet "Working…" after the title (a spinner reads as thinking, where a dot in the middle of the header read as strange); finished is a check mark in the icon slot and "Done" until the user looks at the panel.
- **Tab pill** (`chrome/PillActivity.tsx`, one line in `TabPills`): one mark at a time, in the pill's leading padding so it never squeezes the tab's name (a pill with a spinner and a check once showed "Age…"): a small spinner in the accent while any of its panels works, which beats the check. A finish the user didn't see (the tab hidden or the window not in front) makes the pill glow once in the finished agent's color (`--wc-glow-agent` set on the glow element with `data-agent`: a ring and tint in that color, a halo of its luminous tint, breathing in and fading out over `--wc-dur-glow` 1.2 s on `--wc-ease-gentle`, the panel glow's curve; clearly visible but soft), then a calm check mark in that color until the user shows that tab. Several agents finished unseen in the tab: the latest finisher's color (`store/activity.ts` keeps the color, from the catalog like the panel's glow, and the finish order with each finish, memory only), and each new unseen finish glows the pill again. An agent the catalog doesn't know: the accent (`--wc-glow`, a touch of the warm tone in the halo) and the success check. Under reduced motion `--wc-dur-glow` is 0: no glow, just the mark.
- **The panel's finish glow** (`panels/PanelGlow.tsx` in each block card, rules in `chrome/finish-glow.ts`): the reward, on the finished agent's own block, never the window. The block's rounded inner edge glows once (a short haze fading inward and a thin bright line on the edge): it swells up slowly and fades out softly, one breath, about 2.8 s (`--wc-dur-finish-glow`, `--wc-ease-gentle`). Nothing moves around the block (a light circling the panel read as strange). Only the agent's color (`--wc-workspace-<color>`): a gradient between it and a lighter, luminous tint of the same hue; no accent, no warm tone. Calm and celebratory, never alarming. A CSS overlay inside the card, above its header and body, that nobody can point at, hidden and still while idle; opacity and transform only (static masks).
  - **When it fires:** a finish in a panel the user isn't looking at. On screen (its tab shown, not parked behind a maximized panel, the window in front) but not focused, it plays at once; otherwise it waits and plays when the panel comes on screen: its tab or workspace shown, the maximize ended, or the window back in front (focus or visibility), so the user sees it.
  - **When it stays quiet:** a finish in the panel the user looks at (focused, the window in front); a finish never glows twice; `appearance.finish_glow` off (Settings › Appearance › Glow the panel when an agent finishes, on by default); reduced motion (no glow, the marks stay). Each panel glows on its own: two agents finishing glow their own blocks, each in its color.
  - **How:** a pending glow per panel (`pendingGlows`, memory only), set on such a finish (waiting, or ready when on screen), made ready by the wiring when the panel comes on screen, and cleared when the card plays it or the panel goes. The card's `PanelGlow` listens to its own panel's entry outside React and plays through a ref (`data-glowing`, the agent's color as `--wc-finish-glow-agent`): no card re-renders, no timers.
- **Workspace switcher:** a hidden workspace's row says "Working" or "Done"; the switcher button shows a small accent dot while any hidden workspace has one.
- **Window not in front:** a finish flashes the taskbar button until the window comes forward (`platform::flash_taskbar`: `FlashWindowEx` with `FLASHW_TRAY | FLASHW_TIMERNOFG`; elsewhere the window's user-attention request) and, with `agents.notify_when_done` (default on), shows a system notification "Claude Code finished" / "in <tab>". Only the agent's and the tab's names, never terminal content. Clicking it brings the window forward and shows that tab and panel (`show-panel` event).
- Notification: a minimal Windows toast through `platform/` (WinRT `ToastNotification` from the `windows` crate already used), not `tauri-plugin-notification`: the plugin can't report a click on Windows, and the toast needs no new dependency. The toast uses the app's identifier (the installer's Start menu shortcut carries it) and, in a dev build run from `target\`, PowerShell's id like the plugin does. Other OSes: no notification yet (the flash only).

## Rendering
The store changes only on state changes (a few per agent turn). The pill and the header subscribe with selectors that return strings, so they re-render only when their own state changes; `TabView` cards never re-render for activity. Nothing in React runs per output chunk.

## Tests (named N-06)
- Rust: the watch with recorded byte and title sequences on a fake clock (echo ignored, sustained output, quiet → idle, start-up and restore output ignored until a submit, title rules once matched, each built-in pattern with recorded titles); the title taken from the VT state; the TOML field (bad regex refused for plugins); the setting's default and load.
- UI: the store (finished only when unseen, the pill's done until its tab is seen; the finisher's color, the latest finisher winning), the header and pill states (one mark, working beats done; the glow and the check in the finisher's color, a second finish glowing again in its own) and the glow under reduced motion; the panel glow's rules (on screen and not focused it plays at once; it waits for the tab, the maximize's end or the window's return; never for the focused panel; once per finish; each panel on its own; the setting off and reduced motion keep it quiet), its overlay in the card (no terminal re-renders), and the wiring (tabs, maximize, focus and visibility).
- E2E: a stand-in `claude.cmd` that sets a spinner title and prints for a few seconds after a line is typed, then sets the idle title: working on the background tab's pill, then the pill's glow and the done mark, cleared when the tab is shown, and the agent's panel glowing then (and again when its workspace comes back); a finish in the shown tab with another panel focused glows the agent's panel at once; a finish in the focused panel glows nothing. The showcase freezes the glows (their animations paused and sought): Claude Code's and Codex's panels glowing together, each in its color, dark and light, and a frame sequence (`glow-frames-*.png`).
